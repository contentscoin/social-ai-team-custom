# Social AI Team — 기능 고도화 기획서

## 0. 한눈에 (Executive Summary)

Social AI Team은 **한국 SMB를 겨냥한 소셜 콘텐츠 자동화 팀 시스템**으로,
`/content-director` 오케스트레이터 아래 8개 채널 라이터·비주얼/영상 레인·컴플라이언스
게이트를 두고, 그 위에 **온에어 데스크(Electron 컨트롤타워)**·**OpenCrab 지식
오케스트레이션**·**직접 발행 API**까지 갖춘, 이미 상당히 성숙한 제품입니다.

핵심 설계 원칙("한국어로 말하고, 영어로 계약한다", 승인 게이트 회수, 병렬 팬아웃의
disjoint-폴더 안전조건, 원자적 쓰기)은 견고합니다. 그러나 8개 서브시스템을 코드
근거로 분석한 결과, 고도화의 방향은 **새 기능을 얹는 것보다 "이미 광고된 역량을 실제로
완성하고, 끊긴 루프를 잇는 것"**에 있습니다. 대표적으로:

- **"다층 폴백"은 문서에만 존재** — 렌더 엔진은 단일 프로바이더만 호출하고 실패 시 그냥
  멈춥니다(`render.js`). 스킬의 기본 엔진(Nano Banana)이 데스크톱 코드에는 아예 없습니다.
- **팀은 8개 채널을 쓰는데 기획은 5채널만** — 캘린더는 Instagram/LinkedIn/Facebook/
  TikTok/X만 다루고, 실제로 카피를 쓰는 카카오채널·네이버클립 라이터는 오케스트레이터에
  **한 번도 배선되지 않았습니다**(`grep` 매치 0건). 게다가 네이버클립 출력 폴더가
  비디오 레인과 충돌해 병렬 안전 전제가 깨집니다.
- **발행→성과→다음 기획 루프가 100% 수동** — 발행 로그는 "무엇을 언제 올렸나"만 남고,
  그 성과를 되가져오는 코드가 없어 매달 클라이언트가 CSV를 수기 익스포트해야 합니다.
- **테스트 0개 · 문서 드리프트 · 반쪽 자동업데이트** — 리포지토리 전체에 테스트가 없고,
  스킬 개수가 문서마다 10/17/19로 다르고 저장소 URL이 3종이며, 코드사이닝 부재로
  macOS 자동업데이트가 차단됩니다.
- **보안·데이터 거버넌스 공백** — 발행 토큰이 평문(`secrets.json`)으로 저장되고,
  백업/복원·스키마 마이그레이션이 없으며, 외부 콘텐츠(레퍼런스 URL·팩)를 LLM에
  주입하면서 간접 프롬프트 주입 방어가 없습니다. LLM 출력이 시스템의 핵심 계약인데
  이를 검증하는 golden-set 회귀 평가도 없습니다.

이 기획서는 이 갭들을 **6개 전략 테마**로 묶고 **Now / Next / Later 3단계 로드맵**으로
배치합니다. 단기에는 "실제 버그이자 저비용 고효과"인 항목(채널 배선, 계약 통일, 발행
재시도, 테스트 기반, AI 표시 의무)에 집중하고, 중기에 엔진 신뢰성과 컴플라이언스
데이터화를, 장기에 폐루프 데이터·협업·지식 자산화를 완성합니다.

## 2. 전략 테마 6가지

개별 개선안 50건을 관통하는 6개 테마입니다. 로드맵은 이 테마를 단계적으로 완성합니다.

### T1. 8채널 배선 완결 — "팀이 쓰는 모든 채널을 전 구간에서 지원"
팀은 Instagram·Threads·LinkedIn·X·네이버블로그·네이버클립·카카오채널·Facebook을 다루지만,
기획(캘린더)·오케스트레이션·발행이 이 집합을 온전히 커버하지 못합니다. 기획→카피→비주얼→
컴플라이언스→발행의 모든 레인을 8채널로 맞춥니다.

### T2. 엔진 신뢰성 — "문서상 개념을 동작하는 코드로"
다층 폴백, 이미지 QA 루프, 릴스 클립 체인 실행, 발행 재시도 — 전부 문서에는 있으나
코드에는 없습니다. 이들을 실제 실행되는 코드로 완성해 "무검증·무재시도"로 나가는 산출물을
없앱니다.

### T3. 폐루프 자동화 — "발행에서 성과, 성과에서 다음 기획까지"
지금은 사람이 매달 수동으로 잇는 발행→성과→기획 루프를 데이터로 연결합니다. 플랫폼 인사이트
자동 수집 → 구조화된 best-performers → 콘텐츠 ROI/실험 → 다음 캘린더 자동 반영.

### T4. 컴플라이언스 현행화 — "규칙을 데이터로, 변하는 규제를 무수정으로 추종"
표시광고법·업종 금칙·밴리스트를 SKILL 본문에서 버전 관리되는 데이터(YAML)로 분리하고,
결정적 검증 스크립트와 AI기본법 대응(표시 의무 상향)을 도입합니다.

### T5. 제품 기반 신뢰 — "테스트·문서·배포·관측성 + 보안·데이터 거버넌스"
테스트 0개, 문서 드리프트, 반쪽 자동업데이트, 비용 무통제를 정리합니다. 여기에
**토큰 암호화·백업/스키마 마이그레이션·LLM 계약 회귀 평가·프롬프트 주입 방어**까지
포함해, 비기술 사용자가 믿고 쓰는 배포 품질과 운영 가시성·보안 기준을 확보합니다.

### T6. 지식 자산화 — "OpenCrab을 실제로 켜고, 협업 기반을 놓는다"
과소활용된 OpenCrab 역량을 실측 카탈로그 기준으로 재배선하고, 클라이언트 지식을 조직
자산으로 축적하며, 멀티유저 협업의 첫 단계를 놓습니다.

## 3. 로드맵 (Now / Next / Later)

임팩트(효과) × 난이도(비용) × 의존성으로 우선순위를 매겨 3개 호라이즌에 배치했습니다.
난이도는 대략 S(≤1인일) / M(2~4인일) / L(5인일+)입니다.

8. **토큰 safeStorage 암호화 이관** — `masked()` 경계가 IPC 레벨(sec:get/sec:set 모두 masked만 반환)에서 이미 강제되고 있어 `secrets.js` load/save 내부만 교체하면 되는 저비용 항목(검증 확인). Linux 키링 부재 폴백만 선결. 락 데드락 퀵픽스(스테이지 타임아웃)와 묶어 1–2일.

- **프라이버시** — 크로스클라이언트 메타 전략은 클라이언트 데이터 교차 노출 리스크가

  전제입니다. 그전까지는 규칙 기반으로 시작합니다.
- **하드코딩된 비용·크레딧** — 자동 캐스케이드·재생성 루프·인사이트 폴링은 유료 크레딧을
  연쇄 소모할 수 있어, **상한·사전 경고·유료→무료 강등**을 반드시 함께 설계합니다.

  비용(주체가 개인인지 법인인지 결정 포함)이 발생합니다. Next 착수 시 조기 발주 권장.
- **개인정보보호법(PIPA)** — 성과 수집 시 개인 댓글·유저 식별 데이터의 저장 최소화,
  클라이언트 해지 시 팩·이력 삭제(파기 의무), 클라이언트 간 데이터 격리를 T3/T6 착수 전에
  정책으로 정의해야 합니다. AI기본법만이 아니라 PIPA도 컴플라이언스 대상입니다.
- **간접 프롬프트 주입** — 레퍼런스 URL 인제스트·OpenCrab 팩·성과 API 응답은 전부 외부
  유입 텍스트입니다. 발행 자동화 수준을 올릴수록 이 공격 표면이 커지므로, 주입 방어
  계층(Next)을 자동 발행 확대의 **선행 조건**으로 취급합니다.
- **콘텐츠 권리·라이선스** — AI 생성 이미지의 저작권 지위, 제품 사진 합성 시 제3자
  저작물·초상권, 폰트 임베드(@font-face data URI)의 재배포 라이선스, 릴스 음원 라이선스는
  별도 검토가 필요합니다. 권리 대장(rights ledger)이 그 기록 장치입니다.
- **크로스클라이언트 이해충돌** — 익명화만으로는 동종 업종·동일 상권 SMB 간 전략 유출
  문제가 해소되지 않습니다. 계약상 동의 근거와 업종·상권 단위 격리 설계가 필요합니다.
- **측정 수단 선행** — 배치 소요 단축률·업데이트 성공률 같은 지표는 측정 수단(인사이트
  탭·텔레메트리)이 먼저 있어야 합니다. 수치 목표는 측정 수단 확보 후 베이스라인 대비로

## 부록 B. 분석 방법론

이 기획서는 8개 서브시스템을 각각 독립 분석가가 **실제 코드·SKILL 파일을 읽고**
현황·강점·갭(근거 인용)·개선기회(임팩트/난이도/의존성/성공지표)로 구조화한 결과를,
프로덕트 리드 관점에서 중복 제거·우선순위화·로드맵 배치한 것입니다. 갭 근거는 파일
경로·라인 단위로 명시되어 있어 각 항목을 착수 티켓으로 바로 전환할 수 있습니다.

v1.1에서는 별도의 **독립 완결성 크리틱**(코드베이스 대조 검증 포함)을 돌려 다음을
반영했습니다: 토큰 암호화·백업/마이그레이션의 Now 승격, LLM golden-set 회귀 평가와
프롬프트 주입 방어의 Next 하드 게이트 추가, AI기본법 BLOCK의 단계적 상향 완화,
YouTube Shorts·모바일 원격 승인·권리 대장 신설, PIPA·이해충돌·측정수단 선행 리스크
보강, 임의 수치 지표의 베이스라인 대비 재정의. 크리틱이 지적한 "제품·시장 트랙
(경쟁 차별화·과금 모델·사용자 검증)"은 엔지니어링 로드맵 밖의 별도 논의로 남겨둡니다 —
제품 오너 결정이 필요한 영역입니다.

v1.2에서는 Now 11개 항목과 Quick Win 8건 전부를 **v0.18.6(f764abb) 코드와 파일:라인
단위로 대조 검증**했습니다(독립 검증 12건 병렬 실행 + 커버리지 크리틱). 결과: 8개 항목
유효 확인, 3개 항목 티켓 범위 수정(계약 필드 — 코드 파서는 이미 case-insensitive,
락 — 원인은 프로세스 사망이 아니라 행(hang), kr-voice — 에이전트 레이어 적용 기구현),
